# frontend

فضای کار فرانت‌اند.

## وضعیت فعلی

هنوز کدی نوشته نشده. تنها چیزی که اینجاست، مرجع معماری است:

| مسیر | چیست |
|---|---|
| `docs/samakyar-architecture.md` | معماری قالب سمعک‌یار ۰.۳۵.۳ — قواعد، قرارداد نام‌گذاری، چک‌لیست صفحهٔ جدید، و بدهی‌های وضعیت فعلی. همهٔ عددها با اجرای دستور روی خودِ کد سنجیده شده‌اند. |

## چرا هنوز کدی نیست

ساختن صفحه به پنج تصمیم بستگی دارد که هنوز گرفته نشده‌اند.
تا آن‌ها روشن نشوند، هر کدی که نوشته شود احتمالاً دوباره‌کاری است.

### ۱ · کدام سایت؟

دو خوانش از درخواست ممکن است:

- **الف — صفحه‌های تازه برای همین سایت سمعک‌یار.** یعنی ادامهٔ همان قالب
  با همان قواعد. در این حالت `frontend/` جای فایل‌های قالب فرزند است و
  ساختار `parts/` + `acf-json/` + `assets/css/` عیناً ادامه پیدا می‌کند.
- **ب — سایت دیگری (مثلاً `widgeta.app`) با همین منطق.** در این حالت
  فقط *اصول* منتقل می‌شوند، نه پست‌تایپ‌ها و ماژول‌ها.

این دو مسیر کاملاً متفاوت‌اند.

### ۲ · اگر «ب» است — چه چیزی واقعاً منتقل می‌شود؟

قالب سمعک‌یار برای یک کلینیک فیزیکی با محتوای فارسیِ ادمین‌محور ساخته
شده. بخش زیادی از آن مخصوص همان کسب‌وکار است:

| منتقل می‌شود ✓ | نمی‌شود ✗ |
|---|---|
| الگوی «یک بخش = یک فایل + یک گروه + `order.php`» | ۷ پست‌تایپ (خدمت، آزمون، تیم، نظر، برند، سؤال، نوبت) |
| دروازهٔ بخش (`sy_has` / `sy_gate`) | رزرو نوبت، OTP، پیامک |
| آبشار سه‌طبقهٔ متن (`sy_label`) | درگاه اقساط، ووکامرس |
| آبشار رابطه (`sy_*_for`) | دروازهٔ تعهد **پزشکی** — ولی خودِ الگو ارزش انتقال دارد |
| «یا مقصد واقعی، یا هیچ» | نگاشت لینکِ فارسی (`sy_url`) |
| «هیچ نسخهٔ دومی از حقیقت» | مجموعهٔ آیکون پزشکی |
| معیار پذیرش «فیلد خیالی صفر» | توکن‌های فیروزه‌ای درمانی |
| زنجیرهٔ استایل و قرارداد `template_slug` | |

یعنی از ۳۲ ماژول `inc/`، شاید ۶ تا مبنای کار باشند.

### ۳ · استک؟

اگر مقصد `widgeta.app` است، سند تحویل خودش می‌گوید:
> Recreate these designs in the target codebase's environment and patterns
> (Next.js/React or equivalent; choose an SSR-capable framework if none exists
> — SEO is the product's core promise).

این با «قالب وردپرس + ACF Pro» یکی نیست. اگر وردپرس است، آن جمله را
نادیده می‌گیریم؛ اگر Next.js است، ACF Pro از معادله بیرون می‌رود و
معماری باید به یک CMS دیگر یا فایل محتوا نگاشت شود.

### ۴ · فایل‌های طرح `.dc.html` هست؟

همهٔ صفحه‌های سمعک‌یار از فایل طرح پورت شده‌اند. اگر برای صفحه‌های جدید
هم فایل طرح هست، پورت مو‌به‌مو می‌شود. اگر نیست، یا باید اول طراحی شوند
یا از کامپوننت‌های موجود سرِهم شوند.

زنجیرهٔ ابزار پورت (`tools/install-port.py`, `wire-links.py`) در بستهٔ
قالب نبود. اگر در دسترس نیست، کد دستی نوشته می‌شود — و آن‌وقت پیشنهاد
می‌شود به‌جای کلاس‌های `svc-p###` نام معنادار بگذاریم
(الان ۶۶٪ سلکتورها شماره‌دارند — بند ۷٫۴ سند معماری).

### ۵ · آن پنج توکن متناقض، کدام درست است؟

`--sy-body`, `--sy-muted`, `--sy-r-btn`, `--sy-r-card`, `--sy-surface-2`
در `tokens.css` و `style.css` مقدار متفاوت دارند و `style.css` برنده
می‌شود. تا این تثبیت نشود، کد جدید نمی‌داند کدام را بردارد.

## گام بعد

فهرست صفحه‌ها را بدهید (نامک + اینکه هرکدام Page Template است یا CPT
جدید یا چیدمان تازهٔ یک CPT موجود). نقشهٔ فیلد و بخشِ هر صفحه قبل از
نوشتن کد نوشته می‌شود.
