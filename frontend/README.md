# frontend — widgeta.app

فضای کار فرانت‌اند سایت **widgeta.app**.

## فرض کاری

سایت با همان معماری قالب سمعک‌یار ساخته می‌شود: **قالب وردپرس + ACF Pro**،
صفحه‌های کاملاً داینامیک، هر بخش یک فایل، همهٔ محتوا از فیلد.

سمعک‌یار **مرجع الگو** است، نه کدِ مبدأ. هیچ پست‌تایپ، ماژول یا توکنی از
آن کپی نمی‌شود؛ فقط قواعد معماری‌اش منتقل می‌شوند.

> سند تحویل طراحی Widgeta پیشنهاد Next.js/SSR داده بود. این تصمیم کنار
> گذاشته شد: وردپرسِ درست‌ساخته هم SSR است و وعدهٔ اصلی محصول (سئو) را
> تأمین می‌کند. اگر نظرتان چیز دیگری است، بگویید — قبل از نوشتن کد
> عوض‌کردنش ارزان است.

| منتقل می‌شود ✓ | نمی‌شود ✗ |

| دروازهٔ بخش — بخش بی‌داده چاپ نمی‌شود | رزرو نوبت، OTP، پیامک، ووکامرس |
| آبشار سه‌طبقهٔ متن (`sy_label`) | درگاه اقساط |
| آبشار رابطه (`sy_*_for`) | نگاشت لینک فارسی، مجموعهٔ آیکون پزشکی |
| **دروازهٔ تعهد** — الگویش، با تعهدهای متفاوت | توکن‌های فیروزه‌ای درمانی |
| «یا مقصد واقعی، یا هیچ» | فونت یکان‌بخ، ارقام فارسی |
| «هیچ نسخهٔ دومی از حقیقت» | |
| معیار پذیرش «فیلد خیالی صفر» | |
| زنجیرهٔ استایل و قرارداد `template_slug` | |

از ۳۲ ماژول `inc/` سمعک‌یار، حدود ۸ تا مبنای کار می‌شوند — بقیه مخصوص
کلینیک‌اند.

## گام بعد

`docs/widgeta-architecture.md` را بخوانید و سه چیز را تأیید یا رد کنید:

1. **دوزبانگی** — کدام راهکار (بند ۶ سند)
2. **دامنهٔ فاز یک** — کدام صفحه‌ها اول ساخته شوند (بند ۷)
3. **فایل‌های طرح** — بستهٔ تحویل ۵ صفحهٔ طراحی‌شده دارد؛ بقیه هنوز طرح
   ندارند. برای آن‌ها طراحی می‌شود یا از کامپوننت‌های موجود سرِهم می‌شوند؟

بعد از آن، نوشتن کد شروع می‌شود.
